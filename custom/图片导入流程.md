# Forge DIY 图片导入流程

本文件是本项目自定义卡图的长期操作说明。卡牌脚本、版本表与图片的权威源都在 `D:\Forge\forge-latest\custom`；不要只修改 Forge 缓存目录。

## 1. 路径与缓存

| 用途 | 权威路径 / 实际路径 |
|---|---|
| 卡牌脚本 | `cards/<颜色>/<脚本名>.txt` |
| 版本表 | `editions/Placeholder_Set.txt` |
| 图片源 | `cards/pictures/PH01/` |
| Token 图片源 | `tokens/pictures/<TokenScript文件名>.jpg` |
| Forge 默认读取路径 | `%LOCALAPPDATA%\Forge\Cache\pics\cards\` |
| Forge token 读取路径 | `%LOCALAPPDATA%\Forge\Cache\pics\tokens\` |
| 本机卡图实体目录 | `D:\Forge\Cache\pics\cards\` |

本机的 `%LOCALAPPDATA%\Forge\Cache\pics\cards` 是指向 D 盘的 NTFS Junction。游戏和下载器仍访问默认路径，图片实际写入 D 盘，不会继续占用 C 盘的大量空间。

检查联接：

```powershell
Get-Item "$env:LOCALAPPDATA\Forge\Cache\pics\cards" -Force | Format-List FullName,LinkType,Target
```

## 2. 基础图片命名

Forge 按“版本代码 + 卡牌内部名称 + 画面编号”寻找图片。`PH01` 中的卡名必须与脚本 `Name:` 和版本表中的卡名逐字一致，包括中文字符。

### 强制图片内容检查

收到用户提供的图片后，第一步必须实际打开并查看图片内容，再决定导入分支。不得根据文件名、扩展名、分辨率、路径或诸如 `_full`、`full-art`、`card` 等字样推断图片类型；这些名称不构成“完整成品卡图”的证据。

检查时按图片中实际可见的内容分类：

- **纯原画**：只有插画，没有最终牌名、费用、类别栏、规则文字、P/T 和完整牌框。默认走 Forge 动态牌框流程：备份原图、裁成横向约 `1.37:1`、保存为 `.artcrop.jpg`，并在版本表中加入 `@Custom`。
- **完整成品卡图**：图片本身已经包含最终牌名、费用、类别、规则文字、P/T 或忠诚度以及完整牌框。走 `.full.jpg` 直通流程，单画面版本不得加入 `@Custom`。
- **用户明确要求完整扩画**：即使输入是纯原画，也只有在用户明确要求预先生成完整牌面时才调用 Card Conjurer；否则纯原画默认由 Forge 绘制动态牌框。

图片分类只决定卡图处理方式。无论走哪条分支，都必须另外实现用户指定或图片可见的卡牌效果，并补全 `cardnames-zh-CN.txt` 的中文名称、类别和规则文字。

单画面完整卡图：

```text
cards/pictures/PH01/<卡名>.full.jpg
```

例如：

```text
cards/pictures/PH01/破链灾星霍格.full.jpg
```

图片源准备好后，不要手动复制到缓存。运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install_to_forge.ps1
```

安装脚本会将图片同步到 Forge 实际缓存路径。同步后需要重启 Forge，或在开发者模式中重新加载资源。

### 自定义 Token 图片

Token 图片不放进 `cards/pictures/PH01/`。其文件名必须与 `TokenScript$` 引用的 token 脚本文件名一致：

```text
tokens/c_3_3_outlaw_haste.txt
tokens/pictures/c_3_3_outlaw_haste.jpg
```

Token 输入若是纯原画，同样必须先查看图片并裁成适合动态牌框的横向约 `1.37:1` RGB JPEG。`tools/install_to_forge.ps1` 会将 token 脚本同步到 `%APPDATA%\Forge\custom\tokens\`，并将 `tokens/pictures/` 同步到 `%LOCALAPPDATA%\Forge\Cache\pics\tokens\`。同步后应分别核对 token 脚本与 token 图片的源/部署 SHA-256。

## 3. 标准 Forge 文字牌框

Forge 的动态牌框使用插画裁切图（art crop）。它会自动绘制名称、费用、类别、规则文字与 P/T。

单画面的文件名：

```text
cards/pictures/PH01/<卡名>.artcrop.jpg
```

只有同一张牌在同一版本中登记了多个画面时，才使用 `<卡名>1.artcrop.jpg`、`<卡名>2.artcrop.jpg` 等连续编号。

插画应为横向，推荐比例约 `1.37:1`。若将竖图直接放入 `.artcrop.jpg`，Forge 会按实际比例扩大插画区域，可能导致规则文字框没有空间。

版本表对应条目必须带有非空画师字段，Forge 才会在 `Crop` 模式中使用 art crop：

```text
8 M 破链灾星霍格 @Custom
```

全局偏好必须为：

```text
UI_DISABLE_CARD_IMAGES=false
UI_CARD_ART_FORMAT=Crop
```

位置：`%APPDATA%\Forge\preferences\forge.preferences`。

## 4. 完整扩画异画

完整扩画图不是让 Forge 再绘制文字，而是预先生成一张含牌框、文字与原画的完整 JPG。它适合直接使用竖向原画，并可以保留原画延伸到文字框后方。

### 完整成品卡图直通规则

处理用户提供的图片前，必须先实际打开图片并判断图片类型：

- **背景图 / 纯原画**：图片中没有最终卡名、费用、类别、规则文字和完整牌框，默认应走第 3 节的 Forge 动态牌框流程；只有用户明确要求完整扩画时才调用 Card Conjurer。
- **完整成品卡图**：图片已经包含最终文字、法术力费用、类别、规则框、P/T 或忠诚度及完整边框，不得再次调用 Card Conjurer 叠加牌框和文字。

文件名中含有 `_full`、`full` 或类似字样，不得据此跳过图片查看，也不得据此把纯原画当作完整成品卡图。

用户提供完整成品卡图时，直接执行游戏内替换流程：

1. 先从卡图中准确实现可见的名称、费用、类别、数值和规则效果，并补充客户端 `cardnames-zh-CN.txt` 的中文名称、类别和规则文字。中文资源用于客户端文本显示，不得改写成品图上的已有文字。
2. 保持原图比例，转换为 Forge 可读取的高质量 RGB JPEG；不得拉伸或裁掉已有文字和边框，也不得裁取插画、叠加 Forge 牌框或调用 Card Conjurer。
3. 按目标画面编号覆盖 `cards/pictures/PH01/<卡名>.full.jpg` 或 `<卡名>2.full.jpg` 等对应源文件。
   对只使用完整卡图的单画面版本，不要在版本表中添加 `@Custom`；在全局 `Crop` 模式下，`@Custom` 会让 Forge 改查 `.artcrop.jpg` 并阻止完整卡图显示。
4. 执行 `powershell -ExecutionPolicy Bypass -File .\tools\install_to_forge.ps1` 同步到游戏缓存。
5. 对比项目源文件与缓存文件的 SHA-256，确认完全一致。
6. 重启 Forge，或在开发者模式中重新加载资源。

此分支跳过 Card Conjurer、中文翻译查找和重新排版；完整卡图上的现有内容视为最终成品，不得重复绘制。

第二画面的文件名：

```text
cards/pictures/PH01/<卡名>2.full.jpg
```

例如：

```text
cards/pictures/PH01/破链灾星霍格2.full.jpg
```

同一张牌在版本表中登记两次以启用 Forge art index：

```text
8 M 破链灾星霍格 @Custom
8a M 破链灾星霍格
```

画面 1 使用 `1.artcrop.jpg`，是标准文字牌框；画面 2 使用 `2.full.jpg`，是完整扩画异画。两条记录的脚本和游戏规则相同，只有图片不同。

对于多于两张画面的同名卡，继续使用 `3`、`4` 等连续编号，并添加唯一收藏编号，例如 `8b`、`8c`。

## 5. 中文文字来源

完整扩画生成器的**唯一默认中文来源**是桌面 Forge 实际使用的简体中文资源：

```text
D:\Forge\forge-latest\forge-gui\res\languages\cardnames-zh-CN.txt
```

资源格式：

```text
内部名称|中文显示名称|中文类别|中文规则文字
```

解析规则必须严格遵守：

1. 第一列与卡牌脚本 `Name:` 逐字匹配。
2. 第二列直接作为卡图名称。
3. 第三列直接作为类别栏。
4. 第四列直接作为规则文字。
5. 除了把字面量 `\n` 转成实际换行，不得改写、补充、拆分、合并或重新翻译内容。
6. 只有整条翻译不存在时，才回退到卡牌脚本中的英文显示字段。

例如该文件中的霍格原文是：

```text
破链灾星霍格|破链灾星霍格|传奇生物～豺狼人|超级延势\n在游戏开始时，将你起始套牌中每张其他传奇永久物牌复制一张，并将这些复制品洗入你的牌库，然后你获得具有“你操控的永久物不受传奇规则限制”的徽记。
```

生成卡图时必须据此得到：名称“破链灾星霍格”、类别“传奇生物～豺狼人”，以及原文两段规则文字。

可以临时指定另一份翻译文件：

```powershell
--translations "D:\path\to\cardnames-zh-CN.txt"
```

当前新版 Forge 只维护 `forge-gui/res/languages/cardnames-zh-CN.txt` 作为桌面客户端的外部语言资源。扩画默认读取该文件，保证与当前客户端显示一致。

## 6. Card Conjurer Borderless 扩画生成器

最终扩画工具安装在：

```text
D:\Forge\cardconjurer-diy\automation
```

最终固定使用 Card Conjurer 原生最初版 `Borderless` 牌框。该版本左右没有额外遮挡，保留最大的原画展示面积。不要切回项目旧 SVG 牌框或 `Full Art New`。

生成任务 JSON 的关键字段：

```json
{
  "kind": "full_art",
  "template": "borderless",
  "language": "zh-CN"
}
```

中文模式使用微软雅黑并对连续中文自动换行。生物只要存在 `power` 与 `toughness` 就自动添加 P/T 框，不依赖类别栏中是否出现英文 `Creature`。

先启动本地 Card Conjurer：

```powershell
D:\Forge\cardconjurer-diy\start-cardconjurer.bat
```

然后生成单张或批量卡图：

```powershell
cd D:\Forge\cardconjurer-diy\automation
node src\cli.js examples\hogaak-test.json --output out --overwrite
```

输出为 `2010×2814` PNG。确认视觉效果后，再转存或复制为 Forge 所需的 `<卡名>2.full.jpg`，并运行项目安装脚本同步。

## 7. 导入一张新卡的标准流程

1. 使用图片查看工具实际打开用户图片，记录它是纯原画、完整成品卡图，还是用户明确要求生成的完整扩画；禁止仅凭文件名判断。
2. 在 `cards/` 新建或确认卡牌脚本，明确 `Name:`。
3. 在 `editions/Placeholder_Set.txt` 登记唯一收藏编号与稀有度。
4. 严格实现用户提供或成品图中可见的规则效果；显示描述与 `cardnames-zh-CN.txt` 使用用户最终确认的中文措辞。
   用户描述存在明显错字时可以纠正；措辞不符合规则模板时可以标准化；除这两种情况外必须严格保持用户提供的文字，不得自行改写。
5. 把用户原始图片备份到 `tools/card-artwork/<原文件名>`，不得覆盖用户桌面原图。
6. 若是纯原画：裁成横向约 `1.37:1` 的高质量 RGB JPEG，单画面保存为 `cards/pictures/PH01/<卡名>.artcrop.jpg`，版本表条目加入 `@Custom`。Forge 将自动绘制名称、费用、类别、规则文字和 P/T。
7. 若是完整成品卡图：保持原图比例和全部文字边框，保存为 `cards/pictures/PH01/<卡名>.full.jpg`，单画面版本表条目不得加入 `@Custom`。
8. 只有用户明确要求完整扩画时：启动 Card Conjurer，使用固定 `Borderless` + `zh-CN` 任务生成 `.full.jpg`；多画面时使用连续画面编号和唯一收藏编号。
9. 执行 `python tools/lint_card.py <脚本>`、相关契约测试、DIY 全量测试与安装脚本。
10. 对比项目源图片与 Forge 缓存图片的 SHA-256，并重启 Forge或重新加载资源，确认图片分支、牌框、中文文字和效果均正确。

## 8. 常见冲突与解决

| 问题 | 原因 | 解决方法 |
|---|---|---|
| 游戏只显示黑色占位卡面 | `UI_DISABLE_CARD_IMAGES=true` | 改为 `false` 并重启 Forge |
| 动态牌框没有规则文字 | art crop 是竖图，比例不适合 | 使用约 `1.37:1` 的横向 `1.artcrop.jpg` |
| 完整图没有中文 | 翻译条目不存在或名称不完全一致 | 检查桌面 zh-CN 文件第一列与脚本 `Name:` |
| 新图片未显示 | 图片只在项目源目录，未同步；或游戏未重启 | 运行安装脚本并重启 Forge |
| 双画面无法选择或图片错位 | 缺少编号图片或版本表没有第二条同名记录 | 使用 `1.artcrop.jpg` / `2.full.jpg`，添加 `8` / `8a` 等连续条目 |
| C 盘持续增长 | 缓存 Junction 被删除或未生效 | 检查 `%LOCALAPPDATA%\Forge\Cache\pics\cards` 的 LinkType 与 Target |
| 版本表测试拒绝 `8a` | 测试仅允许数字编号 | 允许 `^\d+[a-z]?$`，并保持收藏编号唯一 |
| 中文内容与客户端不一致 | 混用了旧版翻译或人工改写 | 只读取指定的 `forge-gui\res\languages\cardnames-zh-CN.txt`，逐字使用第 2–4 列 |
| 文件名带 `_full` 却只有原画 | 把文件名误当成图片内容 | 必须先打开图片；若没有牌框和文字，仍按纯原画裁成 `.artcrop.jpg` 并使用 `@Custom` |

## 9. 验证与回滚

基础验证：

```powershell
python -m unittest discover -s tests -p "test_*.py"
python tools\lint_card.py cards\red\chainbreaker_hogger.txt
powershell -ExecutionPolicy Bypass -File .\tools\install_to_forge.ps1
```

核对图片源与缓存一致：

```powershell
Get-FileHash `
  .\cards\pictures\PH01\破链灾星霍格2.full.jpg, `
  "$env:LOCALAPPDATA\Forge\Cache\pics\cards\PH01\破链灾星霍格2.full.jpg" `
  -Algorithm SHA256
```

若完整扩画不满意，只需以原始 `<卡名>.full.jpg` 重新运行生成器并覆盖 `<卡名>2.full.jpg`，再同步。原始图始终保留在项目图片目录，不需要从缓存恢复。

若需要彻底撤回第二画面：删除版本表中的 `8a` 条目、删除 `<卡名>2.full.jpg`，执行安装脚本并重启 Forge。不要手动删除 `pics\cards` Junction；它负责将缓存保留在 D 盘。
