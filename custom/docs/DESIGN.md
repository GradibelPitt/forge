# Forge DIY Current Design Decisions

本文件汇总当前有效设计结论。实施历史和原始讨论见 [archive/README.md](archive/README.md)。

## Document governance

日常维护只使用根目录六份主文档及本文件。每个事实只有一个详细权威位置，其他文档通过链接引用。历史 design、plan 和旧根文档完整归档，不删除、不覆盖，但可能已经过时。

## Card scripting boundaries

- 卡牌效果优先用当前 Forge DSL 实现。
- 不得从规则文字推测不存在的 Forge 参数。
- `ValidCards$`、玩家定义、区域移动和现有 AbilityFactory API 应优先复用。
- 只有现有脚本系统无法准确表达且用户明确要求时，才扩展 Java。
- 引擎新增能力必须有独立边界、测试和不会破坏同名官方机制的内部名称。

## Miracle-specific additional costs

`矿车难题` 的弃牌是施放额外费用，不能在结算后用弃牌效应近似，也不能让所有由 `PlayEffect` 施放的方式都免除。Forge 既有奇迹生成路径因此只补充 `AlternativeCost.Miracle` 标记：抽到、展示、时机和替代法术力费用流程不变，费用调整可用 `ValidSpell$ Spell.!Miracle` 精确排除实际支付奇迹费用的那一次施放。免费施放、返照和其他替代费用没有该标记，仍须支付卡牌规定的额外弃牌费用。

## Source-filtered life loss prevention

`LifeReduced` 的来源过滤只用于非伤害生命损失。来源由实际结算 `LoseLife` 或辐射的牌张显式传入；费用、疲劳、法力灼烧等无来源事件继续保持空来源，因此不会误耗“所选来源”的防护。伤害仍在 `DamageDone` 层拦截，因为牌手最终生命减少时，同一伤害批次可能已经合并多个伤害来源。

“埃辛诺斯壁垒”复用“荣耀之路”的 `ChooseSource`、目标记忆与指挥区临时效果结构，并在同一效果上并列 `DamageDone` 与 `LifeReduced` 两个替代事件。二者都以放逐该效果牌作为替代结算，因此任一分支首次命中后都会同时移除另一分支，形成一个而非两个独立护盾。

## Spell categories

法术派系／类别复用 Forge 原生卡牌子类别，不新增平行字段或 Java 关键字。脚本采用 `Types:Sorcery Shadow` 或 `Types:Instant Shadow` 一类写法；`Shadow` 与官方的 `Arcane`、`Lesson`、`Trap` 一样进入 `CardType` 的 subtype 集合，可由现有类型与有效性筛选路径识别。中文类别栏显示为“法术～暗影”或“瞬间～暗影”。

## Deck construction overrides

`IgnoreDeckLimits` 只覆盖非指挥官主牌组的最低数量与同名数量限制，保留卡池、禁牌、自定义卡设置等其他合法性检查。`DeckMinimum:N` 用于声明包含该牌时的最低主牌数量；两者均为构筑政策，不应通过对局内脚本模拟。

## Hearthstone game mode

“炉石传说”是构筑大厅中的独立游戏模式，入口位于“时空竞逐”之后，并替代桌面大厅原先的“魔王／魔王混斗”复选框。旧魔王枚举和引擎实现只为存档与内部兼容保留，不再作为该大厅入口展示。炉石模式与 Commander、Oathbreaker、Tiny Leaders、Brawl、Momir Basic、MoJhoSto 互斥，可与 Vanguard 或 Planechase 组合。

该模式直接以引擎规则设置 30 点初始生命、至少 30 张主牌、7 张起手、10 张手牌上限与逐次递增的空牌库疲劳。每个牌手的每个维持阶段从 Plains、Island、Swamp、Mountain、Forest 中选择一种并化生到手牌；规则来源是不会进入任何区域的瞬时内部对象，因此玩家不会看到神器、徽记或指挥区规则牌。

炉石模式中，生物的已标记伤害不会在 cleanup 重置；死亡接触等仅限本回合的辅助状态仍正常清除。攻击者全部合法宣告后，攻击牌手可为每个攻击生物各选择至多一个由对应防守牌手操控的生物。选择在防守牌手完成普通阻挡后强制应用，同一个阻挡者不能被预留给多个攻击者，阻挡费用及阻挡者自身“不能阻挡”等限制继续生效。飞行与威慑不使用普通 MTG 的阻挡方向，而使用攻击者到目标的反向层级：具飞行的攻击生物可以令不具飞行的生物阻挡，不具飞行的攻击生物不能令具飞行的生物阻挡；威慑同理，且具威慑的攻击者强制一个普通生物阻挡时不要求凑足两个阻挡者。所有反向判定均从 `HearthstoneMode` 的模式守卫之后进入专用 `canHearthstone...`／`validateHearthstone...` 路径；普通构筑的 `canBlock`、威慑最少阻挡者数量与 `validateBlocks` 路径保持不变。

## New-game and legend-rule behavior

需要开局改变规则的牌使用 `NewGame` 静态触发和永久徽记。破链灾星霍格只复制注册牌手当前主牌构筑清单中的其他传奇永久物，并通过唯一永久徽记让其控制者忽略传奇规则；“起始牌组”不按异能结算时的手牌或牌库内容重新计算，因此海盗帕奇斯等牌先离开隐藏区也不会漏掉复制。效果不能依赖霍格之后是否仍在某一区域。独立游戏模式不使用这套规则牌机制。

任务牌采用独立的备牌开局流程：构筑时只能置于备牌且至多携带一张；每张任务可以用 `K:Quest` 列出须由起始主牌分别满足的构筑条件，只有全部满足时才会进入开局选择。单张牌可以同时满足多项条件，因此“开进码头”的武具牌也可作为神器满足史迹条件。选定后将任务正面朝上移入自己的徽记区；牌面未显式指定区域的静止式与起动式异能默认从该区生效，但咒语异能不会因此获得从徽记区施放的权限；触发式异能必须在脚本中显式使用 `TriggerZones$ Command`。单任务限制属于构筑规则，不重复写在牌面上。

任务牌把 `Quest` 登记为合法结界子类别，并只在桌面渲染层复用 Saga 的左右分栏牌框（规则文字在左、插画在右）；其类型仍是 `Quest`，不会冒充 Saga 或 Class，因此不会自动加入 Saga 章节／传记指示物、牺牲规则或 Class 等级与“升级”提示。开进码头为传奇结界，阶段说明按用户文案简化为“初始阶段为0，使用两张海盗牌后达到下一阶段。”；底层以不可见的脚本变量累计本阶段已施放的海盗咒语，每累计两张才增加一个可见 `QUEST` 阶段，增加效果与静止式规则均将阶段硬性限制为最多 3。三个竭绝异能分别以阶段大于等于 1、2、3 解锁，因此已解锁且尚未竭绝的旧阶段异能在后续阶段仍可起动，且不附加法术时机限制。

“启迪者伊利斯”的高地条件同样读取施法者注册的起始主牌构筑，而不是结算时的牌库区域。引擎以 `Count$StartingDeckDuplicateNonlandNames` 按内部牌名合并不同版本、忽略地牌并计算重复的非地牌名；脚本只在结果为零时复制当前手牌。这样对局中已经抓取、磨掉、放逐或新化生的牌不会改变起始套牌判定。

“探险者协会”复用 Forge 原生的分组搭档语义：`启迪者伊利斯` 与 `海中向导芬利爵士` 都声明 `Partner:探险者协会`。Commander 构筑只有在两张传奇角色具有完全相同的非空分组时才允许二者共同担任指挥官；它不与普通搭档或其他分组混用，双指挥官的颜色标识照常合并。

## Superreach

Superreach 允许阻挡任意数量的攻击者，并忽略由相应攻击者自身施加的阻挡限制。它不忽略阻挡者自身条件或全局规则。攻击者的 `Ignore Superreach` 会保留该攻击者的限制。详细入口见 [../KEYWORDS.md](../KEYWORDS.md)。

## Windfury

风怒是共享的回合级额外战斗规则，不为每个生物分别建立触发。主动牌手第一次战斗结束后，只要此时操控至少一个风怒生物，`PhaseHandler` 就插入一组完整战斗阶段，并在该额外战斗开始时重置其全部风怒生物。该阶段只允许风怒生物攻击；此限制由额外阶段元数据明确标记，因此不影响其他卡牌通过 `AddPhase` 创建的额外战斗。每回合标志在 cleanup、强制结束回合和游戏重启时清除。

## Boarding

Boarding 按实体 ID 记录本回合受过伤害的不同友方角色。在完整伤害批次后检查阈值；满足时直接进入战场，不创建可响应的堆叠对象。记录在 cleanup 清空。当前区域移动路径不会在 Boarding 牌之后才进入手牌或牌库时立即重查已经满足的阈值；必须等到下一次伤害批次，这一边界仍待单独修复。

## Chinese localization

内部卡名、脚本文件和能力引用保持不变；显示层使用 `内部名称|中文显示名|中文类别|中文规则文字`。未来以工作区翻译文件作为源，安装时对 Forge 中文资源先备份、按内部名称删除旧 DIY 条目、再幂等追加。该设计尚未实现。

## CardDiscover

新增炉石式发现时使用独立 `CardDiscover` API，不改变 Forge 已有 MTG `DiscoverEffect`。

- 候选来源支持卡牌数据库、指定玩家牌库和指定玩家备牌。
- 所有费用、颜色、类型和类别约束复用现有 `ValidCards$`/`Card.isValid`，条件按现有语法叠加取交集。
- 候选先按内部名称去重，再随机提供最多三个；不足三个提供实际数量；零候选不弹窗。
- 数据库来源创建选择牌；牌库与备牌来源移动选择的实际对象，不复制、不洗牌、不改变未选牌顺序。
- `GameRule` 牌不进入数据库、牌库或备牌发现候选；它们不是可获得的游戏牌。
- `RememberChosen$ True` 只记录最终选择并成功移动的牌，不记录其余已展示选项；后续可用 `doesNotShareNameWith Remembered` 排除所有与真正以此法选过的牌同名的候选。
- 从对手牌库选择时保留原所有者，进入发现玩家手牌后遵循 Forge 既有区域规则。

当前状态为已实现、自动测试通过并部署，尚待客户端对局实测。

## Batch database replacement and permanent colored-spell grants

“弃暗投明”使用独立 `ReplaceCards` API 一次性处理手牌与牌库。替换过程对每个区域做一次线性计划扫描并记录符合条件牌的稳定位置，再从缓存的同法术力值候选桶中随机选择；`GameRule` 在候选缓存建立时即被排除。原牌直接停止存在，新牌通过标准换区路径进入原位置，未找到候选桶的原牌保持不变。移动被替代或阻止时不登记替换名称；成功名称先在本次结算内去重，所有区域完成后才一次性合并。候选缓存只保存 `PaperCard`，避免循环调用发现、重复扫描全数据库、逐牌 `indexOf`、额外位置定位扫描或批量实例化游戏对象；有序手牌另做身份成员校验，Forge 有序区底层列表的标准移除／插入本身仍可能是 O(n)，因此不把整个执行宣称为严格 O(k)。`MatchManaValue$ True` 是显式必填契约，缺失或 `False` 会在任何副作用前拒绝。

替换完成后通过 `GrantSpellRule` 把规则直接登记到施法者的对局状态，不创建永久物或指挥区徽记。该规则直接匹配 `Card.nonColorless` 并使用 `Harmony$ True | HarmonyReduction$ 2`：该牌手拥有的所有有色咒语在游戏内 `Card` 和 `CardView` 获得可见“调和”关键字，自动允许任意颜色支付；即使牌暂由别人施放，标签、减费和支付仍按拥有者规则判定，施放者自己的 Harmony 不会借给别人的牌。减费每点先移除一个具有有色支付选项的固定费用符号，剩余点数再走 Forge 既有通用减费路径，所以 `{1}{U}{U}` 变为 `{1}`、`{3}{U}` 变为 `{2}`。尚未选择的 X／COLORED_X 不会被删除；X 选定并展开为实际应付数额后可以被剩余额度减少。它不复用官方 `Harmonize`，禁止与旧 `ReduceGeneric`／显式 `ManaConversion` 混写，也不改变其他卡牌既有 `ReduceGeneric` 只减通用费的语义。费用计算与实际支付分别从相关玩家注册表读取；热查询只按规则数线性遍历，不访问全局卡牌数据库。规则变化只差分更新手牌与公开区标签，牌库和备牌以 epoch 惰性同步，绝不为每张隐藏牌重建 AbilityText。同一稳定键重复登记为幂等操作，避免多次结算产生不断增长的重复记录；需要累积的效果必须显式填写 `Stacking$ True`。

“神秘访客”每次进战场使用 `NameSnapshot$ OpponentCards | Stacking$ True` 登记独立规则。每层只匹配该次结算捕获的对手牌名：重叠牌名累计每层 `{3}` 减费，后来才出现的牌名不追溯获得旧层，无关牌名始终不匹配。名称范围参与 Harmony 覆盖和可见标签刷新，不能在叠加注册时丢弃快照。用户给定的卡面描述保持不变。

## Card-specific decisions

- **破链灾星霍格：** `{4}{R}{R}{R}{R}` 10/10 传奇豺狼人，Superreach，按注册主牌构筑清单复制其他传奇永久物并授予传奇规则徽记。
- **海盗帕奇斯：** `{R}` 1/1 传奇海盗／恶魔，敏捷；己方海盗进场时从手牌和牌库登场。
- **突牙：** `{2}{R}{R}` 3/3 传奇野兽，敏捷，`Boarding:3`。
- **空中悍匪：** `{R}` 1/2 海盗生物；进战场时从数据库发现一张海盗生物牌。已登记为 PH01 第15号牌。
- **神秘访客：** `{U}{U}` 2/3 人类／牧师／邪术师；每次进场快照任一对手当前全部牌名并叠加一层永久调和与 `{3}` 减费，只影响该层快照内的同名牌。
- **妒意收割者：** 每次施放咒语后按战场、手牌、牌库、坟墓场的优先级自动取得第一张同名对象。该规则不要求“选择”，因此禁止为同一区域的多个同名副本创建玩家选择窗口；连续触发逐张取得，耗尽后静默结束。
- **启迪者伊利斯：** `{3}{U}{G}` 5/5 传奇精灵／德鲁伊；施放时若注册起始主牌中每张非地牌的名称均不相同，化生当前手牌中每张牌的一个复制并置入手中；具有探险者协会，可与海中向导芬利爵士共同用作指挥官。
- **海中向导芬利爵士：** `{U}` 1/3 传奇鱼人／探险家；进场时以整副手牌交换牌库底等量牌；具有探险者协会，可与启迪者伊利斯共同用作指挥官。
- **殒命暗影：** 手牌追踪只接受操控者施放且原始牌名不为 `殒命暗影` 的瞬间／法术。即使前一张殒命暗影已经复制成其他名称，也以 `printedNamed` 识别并跳过，继续保留更早的合格咒语；不存在合格历史时保留 `{0}` 的 `Cleanup` 空壳，允许施放并无效果结算，不再以 `CantBeCast` 阻止。
- **末日预言者：** `{B}{B}` 0/7 术士；对手生物可像攻击鹏洛客一样直接选择它作为攻击目标，完整复用既有 `Card` defender 战斗链，不使用“能阻挡则必须阻挡”，因此召唤失调与是否主动阻挡不影响对手处理它。它受到的已标记伤害不会在清理步骤中移除，己方维持开始时仍消灭所有生物且不能重生。
- **许攸：** 定为 `{1}{B}{U}` 2/3 蓝黑多色传奇人类／参谋，蓝色承载牌库与抓牌操作，黑色承载弃牌及对手资源交换，目标是薪传可用但带有真实对手收益的引擎生物。对手可以将自己将开始的整个抓牌步骤替代为略过该步骤，若选择略过则从许攸操控者的牌库顶抓 0～2 张；被略过的抓牌步骤不会发生其正常抓牌或步骤开始时触发。许攸操控者自己的抓牌一律改从自己的牌库底。已按用户修订删除永久物咒语抓牌能力；保留的瞬间／法术能力只由你从手上施放的咒语触发，牌面将类别限制缩写于能力末尾为“每种类别至多触发一次”，代码仍按你本回合施放过的所有其他咒语之完整牌张类别集合求交集。结算时点改按 `Lilah, Undefeated Slickshot` 的替代式效应结构实现：触发先建立只记住该咒语的临时效应；该咒语正常结算将从堆叠进入坟墓场时，操控者才选择是否改置于自己的牌库顶，选择返顶后再执行抓一张牌。由于许攸的静止式异能将己方抓牌改为从牌库底抓，刚返顶的咒语不会被该次抓牌立刻抓回；被反击或未正常结算的咒语因 `Fizzle$ False` 不会返顶，也不会抓牌。
