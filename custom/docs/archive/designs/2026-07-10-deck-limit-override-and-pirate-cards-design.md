# 构筑限制解除与海盗战测试牌设计

## 目标

实现三张自定义测试牌：`test_解除构筑限制`、`海盗帕奇斯`和`突牙`。其中解除牌必须允许主牌组少于通常的六十张，并覆盖普通四张上限以及卡牌自身的 `DeckLimit:1`；另外两张牌按照`测试牌组1-海盗战.txt`实现登船能力。

## 实现边界

`test_解除构筑限制`需要 Forge Java 构筑验证器支持，因为现有卡牌 DSL 只能调整单卡自身的携带数量，不能让主牌区中的一张牌同时取消最低牌数和其他牌的携带上限。Java 改动只处理主牌组总数量和同名牌数量，不绕过禁牌、卡池、指挥官色组、指挥官数量、备牌或其他特殊分区规则。

`海盗帕奇斯`与`突牙`保持为 DIY 工作区内的卡牌 DSL，不为“登船”新增 Java 关键词。

## `IgnoreDeckLimits`关键词

新增引擎关键词 `IgnoreDeckLimits`。若构筑验证器在主牌组中发现至少一张具有该关键词的牌：

- 主牌组最低数量为一张。
- 主牌组不设最大数量。
- 跳过普通的每个英文牌名最多四张限制。
- 跳过 `DeckLimit:N` 等卡牌自身数量限制。
- 继续执行卡牌是否存在、自定义牌偏好、格式卡池、禁牌、指挥官规则以及特殊牌组分区检查。

该检查先于最低牌数判断和逐牌数量判断，因此优先级高于`海盗帕奇斯`与`突牙`的 `DeckLimit:1`。解除牌必须实际存在于主牌组中；它位于备牌或其他分区时不生效。因此主牌组理论最小值自然是一张。

## `test_解除构筑限制`

- 费用：`0`
- 类别：神器
- 关键词：`IgnoreDeckLimits`
- 显示文本：携带此牌构筑时，你的主牌组可以包含任意数量的牌，且同名牌可以包含任意张。

该牌放在 `cards/colorless/` 并加入自定义版本文件。其文件名遵守工作区现有转换规则。

## `海盗帕奇斯`

- 费用：`R`
- 类别：传奇生物～海盗／恶魔
- 属性：1/1
- 关键词：敏捷、`DeckLimit:1`

登船能力在该牌位于手牌或牌库时生效。每当一个海盗在其拥有者操控下进入战场，能力自动把该玩家手牌和牌库中所有名为`海盗帕奇斯`的牌置于其操控下的战场。处理顺序为手牌后牌库；不展示、不要求选择，也不洗牌。

能力在移动前检查相应区域是否仍存在`海盗帕奇斯`。首个能力把所有副本移走后，由后续帕奇斯进场产生的重复触发会因不存在剩余副本而无效果结束，避免无效的区域移动链。

## `突牙`

- 费用：`2 R R`
- 类别：传奇生物～野兽
- 属性：3/3
- 关键词：敏捷、`DeckLimit:1`

登船能力在该牌位于手牌或牌库时生效。每当一个或多个友方角色受到伤害时，检查本回合中已经受到过伤害的不同友方角色数量。友方角色包括该牌拥有者本人，以及由其操控的所有可受伤害对象，包括生物、鹏洛客、战役和 Forge 支持的其他可受伤害永久物。

同一个对象在同一回合受到多次伤害只计一次。若检查结果至少为三个，自动把该玩家手牌和牌库中所有名为`突牙`的牌置于其操控下的战场。处理方式与帕奇斯相同：手牌后牌库、不展示、不选择、不洗牌，并在区域中已无副本时停止。

统计使用 Forge 已有的本回合伤害历史，例如卡牌的 `wasDealtDamageThisTurn` 属性和玩家的受伤记录；不以伤害事件次数或伤害总量代替不同对象数量。

## 测试与验证

先写失败测试，再实现代码。

Java测试覆盖：

- 仅含一张解除牌的主牌组通过最低数量检查。
- 解除牌允许任意大的主牌组。
- 解除牌允许普通牌超过四张。
- 解除牌覆盖另一张牌的 `DeckLimit:1`。
- 解除牌只在主牌组中生效。
- 解除牌不绕过格式卡池、禁牌及其他非数量限制。
- 不含解除牌的牌组维持现有构筑规则。

Python脚本契约测试覆盖三张牌的名称、费用、类别、属性、关键词、触发区域、过滤条件、批量区域移动、无洗牌行为、版本登记和所有 `SVar` 引用。

最后执行：

- 相关 Forge Java 单元测试。
- DIY 工作区的全部 Python 测试。
- `python tools/lint_card.py` 分别检查三张新卡。
- 构建并验证桌面 Forge 运行包；仅在测试通过后同步 DIY 卡牌与运行包。

## 完成标准

三张牌均能被 Forge 加载并列入自定义版本；构筑验证器只在主牌组包含`test_解除构筑限制`时解除总数量和同名牌数量限制；海盗帕奇斯和突牙在没有解除牌时仍严格限制为一张；两个登船能力按指定条件自动执行且不洗牌。
