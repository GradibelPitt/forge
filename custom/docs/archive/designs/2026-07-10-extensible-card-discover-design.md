# 可扩展“发现”机制与“空中悍匪”设计

## 目标

为 Forge 增加一个炉石式“发现”能力：从指定候选池中按照 Forge 现有卡牌过滤规则筛选，以不重复的牌名随机提供最多三个选项，玩家选择其中一张并将其置入手牌。同时新增自定义卡牌“空中悍匪”。

本机制不得为费用、颜色、类别或牌张类型发明新的过滤语法。所有此类约束均复用 Forge 现有的 `ValidCards$` 解析和 `Card.isValid` 行为，因此多个条件可以按照现有语法叠加并取交集。

## API 与脚本接口

新增独立 AbilityFactory API `CardDiscover`，避免改变 Forge 已有、含义不同的 MTG `Discover` API。

基础形式：

```text
DB$ CardDiscover | Defined$ You | Source$ CardDatabase | ValidCards$ Creature.Pirate | OptionCount$ 3 | Destination$ Hand
```

参数职责：

- `Defined$`：获得发现结果并作出选择的玩家，复用现有玩家定义解析。
- `Source$`：候选池来源。首期支持 `CardDatabase` 和 `Library`。
- `SourceController$`：当来源为 `Library` 时定义牌库所属玩家，复用现有玩家定义解析；缺省为 `You`。
- `ValidCards$`：直接交给 Forge 现有卡牌合法性过滤器，不增加发现专用条件语法。
- `OptionCount$`：最多显示的不同牌名数量，缺省为 `3`。
- `Destination$`：所选牌的目的区域，首期使用并缺省为 `Hand`。

示例：

```text
# 从数据库发现法力值为3且具有海盗类别的牌
DB$ CardDiscover | Defined$ You | Source$ CardDatabase | ValidCards$ Card.cmcEQ3+Pirate

# 从自己的牌库发现符合条件的牌
DB$ CardDiscover | Defined$ You | Source$ Library | SourceController$ You | ValidCards$ Card.cmcEQ3+Pirate

# 从对手牌库发现符合条件的牌
DB$ CardDiscover | Defined$ You | Source$ Library | SourceController$ Opponent | ValidCards$ Card.cmcEQ3+Pirate
```

示例中的合法性字符串最终以当前 Forge 实际支持的 `ValidCards$` 拼法为准；实现和卡牌脚本必须从现有引擎测试或官方脚本中验证具体写法，不得凭示例发明参数。

## 候选池与选择流程

1. 根据 `Source$` 建立候选池。
2. 使用现有 `ValidCards$` 机制逐张筛选；叠加的过滤条件全部同时成立才算候选。
3. 按内部卡牌名称去重。不同版本、画面或版本代码的同名牌只能占一个选项。
4. 随机打乱不同名称的候选集合，截取最多 `OptionCount$` 个选项。
5. 没有候选时直接结束，不打开选择界面，也不创建或移动牌。
6. 只有一张或两张不同名称时，显示实际数量，不补充重复选项。
7. 玩家必须从已显示选项中选择一张；能力结算时不能通过取消跳过选择。
8. 将选择结果放入 `Destination$`。

数据库来源使用所选名称对应的卡牌定义创建新的游戏内牌，然后将其移入手牌。牌库来源使用牌库里的实际卡牌对象，将被选择的实体从其原牌库移入发现玩家的手牌；未选择的牌保持原样，牌库不因查看候选而洗牌或改变顺序。

若对手牌库中的牌被发现，所选实体仍保持原所有者，但进入发现玩家的手牌；其控制与所有权继续遵循 Forge 已有区域移动规则。

## UI 与随机性

发现界面复用现有的单牌选择控制器接口，使桌面客户端、测试控制器和 AI 使用同一结算路径。选项以临时可查看卡牌的形式呈现，但数据库候选中未选择的临时选项不得进入任何游戏区域，也不得触发区域变化事件。

随机抽样使用 Forge 已有随机/洗牌工具，不自行创建随机数实现。测试不依赖固定随机顺序，而验证选项数量、合法性和名称唯一性。

## “空中悍匪”

```text
Name:空中悍匪
ManaCost:R
Types:Creature Pirate
PT:1/2
```

其进战场触发器执行一次 `CardDiscover`：

- 选择玩家为其控制者；
- 来源为可用卡牌数据库；
- 使用现有过滤器要求候选同时为生物和海盗；
- 最多显示三个不同名称；
- 所选牌创建并置入该玩家手牌。

规则文字为：“当空中悍匪进战场时，发现一张具有海盗类别的生物牌。”卡牌加入自定义版本 `PH01`，使用下一个未占用收藏编号。

## 错误与边界处理

- 缺失或无法解析的必要参数沿用 AbilityFactory 当前的脚本错误处理方式，不静默改成不同条件。
- `OptionCount$` 小于等于零时视为没有可提供的选项并直接结束。
- 来源玩家不在游戏中、来源区域不存在或候选池为空时直接结束。
- 数据库中无法构造的卡牌定义不得成为选项。
- 名称去重在随机截取之前完成。
- 过滤条件必须同时适用于数据库卡牌和实际牌库卡牌。

## 测试策略

严格按测试驱动顺序增加测试：先写并运行失败测试，再实现最少代码使其通过。

引擎测试覆盖：

1. 多个 `ValidCards$` 条件叠加时只保留交集。
2. 三个以上合法名称时只提供三个选项。
3. 同名不同版本不会形成重复选项。
4. 只有一或两个合法名称时仅提供实际选项。
5. 无合法候选时不调用选择器且不产生牌。
6. 数据库来源将选择结果创建到手牌。
7. 自己牌库来源移动实际牌对象，不复制、不洗牌。
8. 对手牌库来源移动选中的实际牌，其他牌不改变。

DIY 契约测试覆盖“空中悍匪”的费用、类型、身材、入场触发、过滤条件、版本条目和规则文字。最后运行目标 Java 测试、相关模块测试、Python DIY 测试和 `tools/lint_card.py`。

## 不在本次范围内

- 不改变现有 MTG `Discover` 的含义或行为。
- 不新增发现专用的费用、颜色、类别、类型过滤参数。
- 不实现新的过滤表达式语言。
- 不实现一次发现多张、重选、加权候选或特殊 AI 评分。
- 不修改未选择牌库候选的顺序，也不公开未选择选项给非选择玩家。
