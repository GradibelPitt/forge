# 游戏内 DIY 选择性更新

> 2026-09-09 策略 2 的最新规则见 [DIY_UPDATE_PROTECTION.md](DIY_UPDATE_PROTECTION.md)，包含牌名模糊搜索的明确保护、完整桌面成员目录与类型绑定门禁。下文为策略 1 的实现记录；路径范围和保护能力以新文档为准。

规则脚本内嵌于 `forge-gui` 模块的 `forge/download/diy-updater.ps1`，由 `DiyUpdateBridge` 从游戏的更新按钮调用。它调用 Java 17 JDK 和 Maven 编译，并不是普通 JAR 天生具有自我编译能力。

## 更新边界

- 官方新卡：只合入 `forge-gui/res/cardsfolder` 新增的卡牌脚本；已有脚本保持现状。
- 版本资料：合入 `forge-gui/res/editions` 的新增和修改。
- 引擎：合入 game、ai 以及明确列出的 core 规则/卡牌数据和共享 player Java 源码、对应测试的新增和修改。
- 已有 Java：允许三方合并修改，不接受删除或重命名中的删除操作。重叠冲突立即停止。
- UI、皮肤、翻译、custom 内容、启动器和更新器本身不取官方版本覆盖。
- 相关构建/依赖配置变更必须人工检查；无关移动端文件不参与。牌组不在更新范围内。

基于上次官方提交、当前 DIY 源码和目标官方提交进行三方合并，而不是用官方同名文件替换 DIY 文件。Git 合并并不能证明语义兼容，因此必须继续通过编译、测试及关键 DIY 类存在性检查。

## 安全切换

每次操作位于安装根目录 `updates/versions/<唯一编号>` 的独立源码和应用目录。下载、合并、编译或测试失败均不修改当前游戏。成功后仅原子切换 `updates/active.json`，保留上一版本和日志；当前游戏不被强制退出，保存、关闭并重新通过 DIY 启动器启动后生效。

启动器先完成既有 DIY 资料同步，再校验本地更新的 JAR、资源清单和基线身份。损坏、不完整、越界或过期的更新会回退到已发布 DIY 包。公开 DIY 基线发生变化时优先采用该发布包，旧的本地构建仍被保留。局部源码更新位于运行仓库外，不受该仓库的日常刷新删除。

首次可能下载较多源码和编译工具。Git 沿用启动器准备的版本；缺少 JDK/Maven 时下载官方发布并校验散列。只有运行时不能编译 Java，因此不能省略编译环境。源码构建产物不自动推送到 GitHub；联机双方仍须采用一致构建。

## 诊断

任务结果、更新日志、选择清单位于 `updates/jobs/<编号>/result.txt`、`update.log` 和 `plan.json`。发生冲突时保留隔离源码用于检查，不猜测、自动删文件或切换到官方安装器。

截至 2026-09-09，对官方 `4bee0abda5277ad8b8def2ed1229458bb7121fc0` 的实际比较选择了 643 个路径，4 个路径需要人工处理：`GameEntityCache.java`、`AscendEffect.java` 的删除，以及根 POM、共享 GUI POM 的变更。因此该官方版本没有被自动合入或激活。当前源码的完整引擎回归另有 3 个失败，见 VERIFICATION；不会忽略这些失败来宣称全自动升级成功。
